# 开发对接说明

本仓库的 prompt 由设计侧调好，开发只需按本说明接入。接口细节以 [qwen-image-3.0-pro接入文档.md](qwen-image-3.0-pro接入文档.md) 为准。

## 1. 整体流程

```
内容（主标题/副标题/产品/卖点）
   + 风格配置 styles/<id>/style.json
   + 随机选项（每类抽一项，自动跳过冲突组合）
        ↓  src/poster/prompt.py  build_request()
请求体 JSON
        ↓  POST /unified/v1/images/tasks（无产品图）或 /images/edit-tasks（有产品图）
task_id（202 Accepted）
        ↓  GET /unified/v1/tasks/{id}/wait 循环，直到 completed / failed
data[].url  →  立即转存到自己的存储
```

参考实现：`src/poster/client.py`（提交、幂等重试、轮询、下载），`src/poster/cli.py`（并发出图）。

## 2. 请求体示例（风格1，“每类取第 1 项”）

用下面命令生成，不调用接口：

```bash
PYTHONPATH=src python3 -m poster prompt --style style1-sticker --content examples/content/简单.json
```

请求体字段：

| 字段 | 值 | 能否改 |
|---|---|---|
| `model` | `qwen-image-3.0-pro` | 不改 |
| `prompt` | 由 `build()` 拼接 | **不要手改**，改内容请改 content，改风格请改 style.json |
| `negative_prompt` | style.json 中的 `negative_prompt` | 不改 |
| `aspect_ratio` / `quality` | `3:4` / `2K` | 不改 |
| `provider_options.prompt_extend` | `false` | **不改**：默认 true 会让模型改写 prompt，乱码和版式失控 |
| `n` | 每次出几张，1–6 | 可改 |
| `seed` | 每张随机生成并记录（便于复现同一张图） | 可改 |
| `image` | 产品参考图，1–3 张，HTTPS URL 或 data URL | 有产品图时必传，并改用编辑接口 |

## 3. 内容（content）规则

```json
{ "主标题": "博世新品冰箱", "副标题": "上海首发", "产品": "……外观描述……", "卖点": ["全嵌", "隐嵌", "高品质"] }
```

- 可选词见 [`examples/keywords/冰箱.json`](../examples/keywords/冰箱.json)，按长度分组；三档示例见 `examples/content/简单.json`、`中等.json`、`压力.json`。
- 文字建议 **5 段**：主标题 + 副标题 + 3 个卖点。段数越多、越长，越容易出乱码（压力档用于测试上限）。
- `产品` 是给模型看的**外观描述**，不会作为文字印在图上；不要在里面写英文品牌名或型号（如 Bosch、KCG89AA21C），模型可能把它们画到图上。型号需要展示时放进卖点。
- 建议：主标题 ≤8 字，副标题 ≤6 字，卖点每个 2–4 字。
- 有产品参考图时，再加 `"产品名": "冰箱"`，产品描述会自动替换为“参考图中的冰箱，保持外观、颜色、门体结构和细节完全不变”，`参考图时固定` 中的类别（如产品角度）改为跟随参考图，并用编辑接口传图。

出图前先检查内容（不扣费）：`PYTHONPATH=src python3 -m poster check <内容.json> [--image 产品图]`，有 ERROR 时不要提交出图。

## 4. 必须注意

1. **并发 ≤3，并处理限流。** 并发 3 时仍偶发任务 `failed` 且 `error.code = upstream_rate_limited`：这类失败应等待 10–30 秒后**重新提交**（参考 `cli.py` 的 `run_one`，最多重试 3 次）。
2. **结果链接会过期**，任务正文完成后保留 24 小时，拿到 `data[].url` 后立即下载转存。
3. **幂等：** POST 时带 `Idempotency-Key`（每个出图操作一个 UUID），网络超时用同一个键重试，不会重复扣费。参考 `client.submit()`。
4. **先保存 task_id 再等待。** 等待超时或进程退出不影响任务，用同一 task_id 继续查询即可。查询必须用提交时同一把 API Key。
5. **HTTP 200 也可能是失败**：以正文 `status` 为准（`completed` / `failed`）。
6. **费用核对**：保存响应头 `x-cr-usage-id`。
7. **文字准确率**：模型偶尔会写错字，竖排标题风险更高。上线前建议人工抽检；如对文字要求绝对准确，可改为模型只出图、文字由前端/后端叠加。

## 5. 新增或修改风格

- 改风格：只改 `styles/<id>/style.json`，同步更新同目录 `README.md`。
- 新增风格：复制 `styles/_template/`，改 `id`、`name`、`风格`、`options`、`conflicts`、`template`。
- `template` 是按顺序拼接的片段，`{类别名}` 会替换为抽中的选项，另有 `{风格}` `{主标题}` `{副标题}` `{产品}` `{卖点}` `{文字约束}`。
- `参考图时固定`：有产品参考图时，用这里的文字覆盖对应随机类别。
- `conflicts` 每条规则是 `{类别: 选项序号}`，全部命中即视为冲突，随机时跳过。
